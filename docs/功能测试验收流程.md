# 算力交易平台 · 功能测试与验收流程

> 配套文档：《系统模块功能说明.md》
> 覆盖范围：用户端 15 个模块、管理端 16 个模块、12 条跨模块闭环链路、权限/并发/金额/数据保留专项。
> 用例编号规则：`T-模块-序号`；端到端场景 `E2E-序号`；专项 `S-序号`。

---

## 1. 测试目标与准出标准

### 1.1 目标

1. 验证每个动作的**主流程**、**分支流程**、**异常流程**与**数据闭环**。
2. 验证跨模块资金链路（会员、代采代售、推广佣金、客服委托佣金、退款冲正）**账实一致**。
3. 验证权限隔离：任何角色不能通过直接调用动作越权。
4. 验证幂等、并发、金额精度、状态机不可跳步。
5. 验证无效/过期数据按策略清理，关键数据不可物理丢失。

### 1.2 准出标准（全部满足才可上线）

| 项 | 标准 |
| --- | --- |
| 自动化回归 | `node cloudbase/scripts/verify.mjs` 全部通过，0 失败 |
| 静态检查 | `npm run check --prefix cloudbase` 通过（WXML 28 个文件 + 小程序事件/数据引用） |
| 语法检查 | `node --check` 覆盖 `shared/*.js`、`server/*.js` 全部通过 |
| 同步一致性 | `shared/*.js` 与 `cloudfunctions/admin|user/_shared/*.js` 完全一致 |
| P0 用例 | 资金、权限、退款、提现、合同、收款确认用例 100% 通过 |
| 安全 | 无明文手机号/证件号/银行卡出站；无越权动作；审计可追溯 |
| 资金守恒 | 收款合计 = 已确认收款；佣金合计 = 各级佣金净额；可提现 = 已结算 − 冻结 − 已提现 − 欠款抵扣 |
| 数据闭环 | 每条主链路结束后，源单、流水、佣金、工单、通知状态一致，无悬挂中间态 |

## 2. 测试环境与数据准备

### 2.1 环境

| 环境 | 用途 | 数据 |
| --- | --- | --- |
| 本地内存 Repo | 自动化回归、分支/异常用例 | 每个用例独立种子数据，互不污染 |
| 预发 MySQL | 端到端联调、并发/性能 | 脱敏备份数据 + 手工造单 |
| 管理端浏览器 | UI 验收、角色菜单/按钮 | 预发接口 |
| 小程序开发者工具/真机 | 用户端全流程 | 预发接口 |

### 2.2 基础账号

| 账号 | 角色 | 用途 |
| --- | --- | --- |
| `admin` | 超级管理员 | 全流程审批、财务、配置 |
| `cs01` / `cs02` | 客服坐席 | 工单领取、咨询对接、合同上传、客服业务 |
| `finance01` | 财务专员 | 收款确认、退款、提现打款 |
| `sales01` | 电销专员 | 未下单线索 |
| 用户 A/B/C | 普通用户 | 推广链 A→B→C、会员购买、委托 |
| 用户 D | 企业主体 | 资质核验、普通 / 私密发布 |

### 2.3 种子数据

1. 商品：出售/出租各 2 条（不同品类、城市），1 条草稿、1 条待审核、1 条在售。
2. 需求：求购/租赁各 2 条，预算/数量/截止时间完整。
3. 委托：代采、代售各 1 条，含材料与截止时间。
4. 会员套餐：月/季/半年/年四档，价格与天数已配置。
5. 推广配置：一级 15%、二级 15%、手续费 5%、最低 100、单笔上限 20000、日 3 次。
6. 客服配置：委托佣金 20%、工单超时 30 分钟（不设会员提成）。

## 3. 执行方式

### 3.1 自动化回归

```bash
cd cloudbase
node scripts/verify.mjs          # 域层全量回归（当前 1295 项）
npm run check                    # WXML + 小程序引用检查
for f in shared/*.js server/*.js; do node --check "$f"; done
```

### 3.2 手工端到端

按第 6 章 E2E 场景在预发环境执行；每个场景记录：操作账号、请求动作、关键数据前后值、页面截图/接口响应、结论。

### 3.3 缺陷分级

| 级别 | 定义 | 处理 |
| --- | --- | --- |
| P0 | 资金错误、越权、数据丢失、主链路不可用 | 阻断上线，立即修复并回归 |
| P1 | 分支状态错误、通知缺失、幂等失效 | 上线前修复 |
| P2 | 展示/文案/排序问题 | 可排期 |
| P3 | 体验优化 | 记录待排期 |

## 6. 跨模块端到端闭环场景

### E2E-01 会员购买 → 两级佣金

1. A 邀请 B，B 邀请 C；C 购买年卡（微信支付）。A 为客服绑定用户（两级），B 为普通推广（仅一级）。
2. 校验：`bizOrders` 1 条、`payments` 1 条、`bizAccess` 到期正确。
3. 校验：B 得一级佣金（按 `commissionRate`），A 得二级佣金（按 `level2Rate`）；金额=实收×比例；`paymentId`/`paymentId#L2` 各一条。
4. 校验：客服不因会员支付获得提成（客服佣金只有推广二级与委托佣金，推广佣金已由推广台账记录）。
5. 校验：C 收到开通站内信；三方佣金状态“待结算”。

### E2E-02 会员退款 → 佣金冲正 → 欠款

1. 对 E2E-01 的支付发起退款并审核通过。
2. 校验：收款单“已退款”；`bizAccess` 停用；风险单生成。
3. 校验：待结算佣金直接冲正；可提现扣回；已提现转欠款。
4. 校验：客服工资不受影响（会员支付本就不计客服提成）。
5. 校验：用户收到退款通知；重复退款幂等。

### E2E-03 代采全流程（正常）

1. 用户提交代采委托 → 客服审核通过上架。
2. 会员领取/客服对接 → 登记条件 → 上传居间合同 → 管理员审核归档。
3. 客服锁定唯一对接方 → 登记成交 → 生成服务费账单。
4. 用户上传打款凭证 → 财务确认到账。
5. 校验：委托 `feeStatus=paid`；工单“服务费已到账”；客服委托佣金计提。
6. 客服确认完成 → 委托“已完成”、工单关闭。

### E2E-04 代采退款回滚

1. 对 E2E-03 的服务费退款。
2. 校验：委托回到“服务费待支付”；已完成退回“已成交”；完成信息清空。
3. 校验：账单重开顺延；客服佣金冲正；工单阶段回退“服务费待支付”。
4. 重新收款后可再次确认完成；重复退款幂等。

### E2E-05 委托审核驳回与重提

1. 提交委托 → 客服驳回（填原因）→ 用户修改重提。
2. 校验：同一委托审核工单回到待领取；历史 `stageHistory` 累加；不新建重复工单。

### E2E-06 多客服对接 → 合同锁定

1. 同一委托两个客服分别对接、各建工单。
2. 任一合同上传后执行 `contract.lock`。
3. 校验：唯一对接方生效；另一工单结束；后续收款/成交只作用于锁定工单。

### E2E-07 咨询 P0 拦截

1. 提交命中 P0 规则的咨询。
2. 校验：进拦截箱；不生成工单、不计热度、不发通知；回执中性。
3. 管理端可见拦截记录；7 天后清理。

### E2E-08 举报 → 下架 → 缓存失效

1. 用户举报商品 → 管理员处置并下架。
2. 校验：商品状态下架；详情缓存立即失效；列表不再返回；举报人收到结果。

### E2E-09 推广提现全流程

1. 推广者申请提现 1000 元。
2. 校验：提现单“待审核”；对应佣金冻结；可提现余额减少。
3. 审核通过 → 待打款；财务领取 → 打款中；回填成功 → 已到账。
4. 校验：手续费 5%；净额 950；佣金状态“已提现”；余额与台账一致；用户收到通知。

### E2E-10 提现异常分支

1. 驳回：释放冻结，填原因，用户可见。
2. 撤销：仅待审核可撤；释放冻结。
3. 打款失败：保持占用；可重试或取消；不重复出款。
4. 并发审核/领取：仅一次成功，其余幂等/冲突。

### E2E-11 Apple 结算解冻

1. Apple 渠道佣金处于待结算，即使过冻结期也不可提现。
2. 财务执行 `promote.appleSettle` 确认该月到账。
3. 校验：该月佣金转可提现；其他月份不受影响；重复确认幂等。

### E2E-12 客服工资月度汇总

1. 当月产生委托佣金与退款冲正（会员支付不产生客服提成）。
2. `cs.salary` 查询当月。
3. 校验：工资 = 委托佣金 − 冲正；已发工资欠款从后续月份抵扣；金额两位小数。
