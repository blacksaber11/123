# 算力交易平台 · 系统模块功能说明

> 适用代码基线：`cloudbase/shared`（线上 Node 单体与云函数共用域层）+ `cloudbase/server` + `prototype/admin` + `cloudbase/miniprogram`
> 文档口径：以服务端已注册动作（用户端 112 个、管理端 171 个，合计 283 个）为准，前端隐藏不改变服务端权限。
> 阅读方式：先看 1.3 模块总表定位，再按模块编号查看功能、分支与状态机；跨模块资金链路见第 6 章。

## 1. 系统总览

### 1.1 技术架构

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 客户端 | `cloudbase/miniprogram` | 用户端小程序（首页、货盘、需求、商机、发布、咨询、消息、推广、我的等 27 个页面） |
| 管理端 | `prototype/admin` + `prototype/assets/console.*.js` | 管理后台单页控制台，按角色渲染页面与动作 |
| 接入层 | `cloudbase/server/index.js` | HTTP/云函数入口、鉴权上下文、静态资源、微信/Apple 支付回调、定时任务 |
| 域层 | `cloudbase/shared/*.js` | 动作注册（`router.js`）、各业务域引擎、校验、加密、权限、审计、缓存 |
| 数据层 | MySQL Repo（线上）/ 内存 Repo（测试） | 集合式文档模型 + 唯一索引 + 事务补偿 |

请求链路：`客户端 action` → `router` 鉴权（用户 token / 管理端会话）→ 角色动作白名单 → 参数校验 → 域处理器 → Repo 读写 + 审计 + 站内信 → 统一错误码返回。

### 1.2 角色与数据边界

| 角色 | 标识 | 页面范围 | 核心职责 |
| --- | --- | --- | --- |
| 超级管理员 | `admin` | 全部 24 个页面 | 全部业务、财务、风控、账号、角色、系统设置 |
| 客服坐席 | `cs` | 工作台/商品/需求/工单/咨询/消息/服务/用户/商机/资讯/榜单/风险/客服/推广 | 货盘审核、工单领取与推进、咨询对接、用户服务、推广提现初审 |
| 财务专员 | `finance` | 工作台/财务/推广 | 收款确认、退款、佣金台账、提现打款与对账 |

> 自定义角色可由管理员在“角色权限”页勾选页面与动作；内置角色不可编辑。服务端对每个动作再次校验 `ROLE_ACTIONS`，前端菜单隐藏只是体验层。

### 2.2 关键唯一索引与业务含义

| 集合 | 唯一键 | 保障 |
| --- | --- | --- |
| `users` | `openid`、`refCode` | 一个微信身份一个账号；推广码全局唯一 |
| `sessions` | `tokenHash` | 会话唯一 |
| `favorites` / `follows` | `uid + targetType + targetId` / `uid + targetKey` | 幂等收藏/关注 |
| `newsLikes` | `uid + newsId` | 一人一赞 |
| `commentReads` | `uid` | 每人一条已读位置 |
| `dailyStats` | `date` | 每天一条快照 |
| `referralBindings` | `uid` | 被邀请人只能绑定一次 |
| `commissions` | `paymentId` | 同一笔支付只计佣一次（二级用 `#L2` 后缀区分） |
| `promoterWithdrawals` | `proofNo`、`requestId`、`activeKey` | 单据幂等；同一用户同时只有一笔在途 |
| `promotePayoutItems` | `withdrawalId + seq`、`activeCommissionKey` | 一笔佣金同时只被一条有效出款明细占用 |
| `csBindings` | `uid`（id=csId） | 一个客服绑一个用户；一个用户只归属一个客服 |
| `csAgencyCommissions` | `paymentId` | 同一笔委托服务费只计提一次 |
| `csRatings` | `leadId` | 一张咨询单只评价一次 |
| `agencyContracts` | `leadId` | 一单一合同，驳回重传按版本叠加 |
| `agencyClaims` | `agencyId` | 一条委托只有一个领取锁 |

> 终态记录不能把唯一键置空（云开发把多个 `null` 视为同值），提现/出款采用 `R#<id>` 退休键。

## 3. 横切能力

### C3.1 鉴权与权限

1. 用户端：微信 `openid` 换取 `users` 记录，签发会话 token；手机号可走微信授权或手工录入（`auth.phoneManual`），字段级加密 + 盲索引。
2. 管理端：环境变量引导账号与 `accounts` 集合合并；登录校验口令哈希 + TOTP 动态口令；生产环境缺配置直接拒绝启动，禁止回落到演示口令。
3. 会话：`admin.session` 返回角色、页面、动作快照；角色调整后刷新快照即可生效，无需重新登录。
4. 动作白名单：`can(role, action)` 二次校验；客服、财务、电销均为“最小权限”，敏感动作仅管理员。
5. 临时权限：`accountPermissions` 支持给单个账号追加动作，写入审计。
6. 管理端口令复杂度：至少 10 位，且大写/小写/数字/符号至少三类。

### C3.2 输入校验、加密与出站安全

- 统一 `str / enumOf / normalizePaging / normalizePhone` 校验，超长、类型不符、枚举越界均抛 `VALIDATION`。
- 手机号、身份证、联系人、主体名称等敏感字段使用 AES 加密 + 盲索引；列表默认脱敏（`maskPhone / maskName / maskIdentity`）。
- 出站投影层 `projection.js` 强制检查明文联系方式：公开列表只允许平台允许的字段；命中即抛错，避免批量泄露。
- 聊天监管文本先脱敏手机号/证件号再出站（`redactChatText`）。

### C3.3 缓存、幂等与并发

1. 多级缓存：L1 进程内 + L2 Redis；key 带分组版本号，写操作 `bump` 版本即可整体失效；Redis 故障自动降级 L1，连续失败熔断。
2. CAS 抢占：收款确认、提现审核、退款处理均使用 `updateWhere(旧状态)` 抢占，失败方读取最新状态做幂等返回。
3. 唯一索引兜底：计佣、评价、合同、领取锁均依赖唯一键防重复。
4. 回调幂等：微信/Apple 支付与退款回调按 `paymentId / outTradeNo` 查重；重复回调只补状态不重复入账。

### C3.4 审计、通知与数据保留

- 管理端写操作统一 `appendAudit`：操作人、动作、目标、原因、结果、时间；审计保留 180 天。
- 站内信 `outbox` + `notifyUser`：开通、收款、退款、提现、工单等关键节点通知；通知失败不回滚主业务。
- 定时任务：会员到期提醒、工单超时结束、委托截止自动关闭、提现结算/对账、日快照、行为事件 90 天清理、聊天媒体 30/7 天清理、拦截箱 7 天清理。
- 系统日志与登录日志：`log.list` / `log.system` 供管理员排查。

## 4. 用户端模块

### U01 用户登录与身份

| 动作 | 功能与逻辑 | 分支/异常 |
| --- | --- | --- |
| `auth.login` | 按 `openid` 建或更新用户，返回不含权限敏感字段的资料；新用户初始化推广码、默认资料 | 无 openid → `VALIDATION`；被封禁 → 拒绝登录并提示 |
| `auth.phone` | 微信手机号授权绑定，加密落库 + 盲索引，返回脱敏号 | 已被其他账号占用 → `CONFLICT` |
| `auth.phoneManual` | 手工录入手机号（无微信授权时兜底），同样加密与判重 | 格式错误/占用 → 校验失败 |

逻辑要点：同一 openid 始终命中同一账号；手机号只作为联系方式与检索索引，不作为登录主键。

### U02 个人资料、主体与隐私

| 动作 | 功能与逻辑 |
| --- | --- |
| `profile.get` | 返回当前用户资料，敏感字段脱敏；带主体类型、认证状态、隐私开关 |
| `profile.save` | 保存昵称、联系人、主体名称、地区等；敏感字段字段级加密；主体类型枚举校验 |
| `profile.privacy` | 保存隐私设置（是否展示联系方式、是否允许被搜索等） |
| `profile.bootstrapSubject` | 首次选择主体类型（个人/企业/机构等）并初始化对应资料结构 |
| `material.sign` | 为上传材料签发直传签名/路径，限制类型与大小，登记 `files` |

分支：主体类型只允许 `SUBJECT_TYPES` 枚举；企业主体缺资质时进入“待核验”，不阻断浏览但阻断发布（由前端与服务端共同约束）。

### U03 算力商品（出售/出租）

| 动作 | 功能与逻辑 | 分支/异常 |
| --- | --- | --- |
| `product.publish` | 发布出售/出租商品；`draft=true` 存草稿（字段可不全、不展示），否则直接上架“在售” | 缺型号/价格/城市 → 校验失败；命中风控 → 进入拦截箱或待审核 |
| `product.submit` | 提交审核（草稿 → 待审核） | 重复提交幂等；已下架需重新提交 |
| `product.update` | 修改本人商品；已成交不可改价 | 非本人 → `FORBIDDEN` |
| `product.delete` | 软删除本人商品 | 有进行中工单 → 拒绝或转下架 |
| `product.offline` / `product.online` | 本人下架/重新上架 | 审核未通过不可上架 |
| `product.list` / `product.detail` | 货盘列表与详情；详情计数、卖家信息脱敏、联系方式按权限释放 | 已下架详情仅本人/管理员可见 |
| `view.count` | 浏览计数，按天去重 | 高频请求走计数窗口 |
| `owner.home` | 货主主页：在售商品、成交记录、评分 | 匿名货主使用匿名键 |
| `mine.publish.list` / `mine.publish.detail` | 我的发布：商品/需求/委托聚合列表与单条详情，按状态筛选 | 分页参数归一化；非本人发布不可查详情 |

商品状态机：`草稿 → 待审核 → 在售 → 洽谈中 → 已成交`，旁路 `已驳回`、`已下架`；草稿可直接删除，已成交不可回退（管理员只能下架展示）。

### U04 求购/租赁需求

| 动作 | 功能与逻辑 | 分支/异常 |
| --- | --- | --- |
| `demand.publish` | 发布求购/租赁；草稿或直接“求购中” | 预算、数量、截止时间校验 |
| `demand.submit` | 草稿提交审核 | 重复提交幂等 |
| `demand.update` | 修改本人需求 | 已关闭/已对接不可改核心字段 |
| `demand.close` / `demand.reopen` | 关闭 / 重新开启 | 关闭后不再进入匹配与商机池 |
| `demand.delete` | 软删除 | 有关联工单需先关闭 |
| `demand.list` / `demand.detail` | 求购池列表/详情；联系方式脱敏 | 已关闭仅本人可见 |
| `demand.responses` | 卖家对需求的响应/报价列表 | 仅需求所属人可看完整响应 |

需求状态机：`草稿 → 待审核 → 求购中 → 已对接 → 已关闭`，旁路 `已驳回`、`已下架`。

### U05 库存管理

| 动作 | 功能与逻辑 | 分支/异常 |
| --- | --- | --- |
| `stock.save` | 保存库存型号、数量、单价、成色、单位、城市、描述与上下架状态（在售/已下架）；id 由客户端预生成，已存在则更新、否则新增；`images` 未传时保留原图 | 型号或城市缺失、数量非 1–100000 整数、单价非 1–999999999 → `VALIDATION`；置为在售时主体与联系方式不齐 → 拒绝保存；非本人库存 → `FORBIDDEN`；更新时记录已被改动 → `CONFLICT`「库存已变化」；未删除库存达 200 条上限 → `CONFLICT` |
| `stock.list` | 我的库存列表：只按 `ownerId` 取未删除记录，按保存时间倒序，上限 200 条 | 超过 200 条只返回最近保存的 200 条；无鉴权上下文返回空列表 |
| `stock.remove` | 软删除本人库存，历史数据保留可追溯 | 记录不存在 → 返回 `removed:false`（幂等）；非本人 → `FORBIDDEN` |

库存是商机匹配的输入：会员开通后，系统按“品类 + 型号 + 城市”与需求/委托匹配，生成可领取商机卡片。

### U06 商机会员与领取

| 动作 | 功能与逻辑 | 分支/异常 |
| --- | --- | --- |
| `biz.plans` | 返回月/季/半年/年四档套餐（价格、原价、天数），来源系统设置 | 设置缺失回落默认 99/268/499/899 |
| `biz.status` | 当前会员状态、到期时间、剩余天数 | 到期自动置“已到期” |
| `biz.badge` | 红点/角标：可领取商机数、待办数 | 无权限返回 0 |
| `biz.cards` | 商机卡片列表：需求/委托聚合，按匹配度与时间排序 | 未开通只返回脱敏摘要 |
| `biz.list` | 可领取商机明细列表 | 分页 |
| `biz.claim` | 领取商机；写 `bizClaims`，记录领取人、时间 | 重复领取幂等；委托类受独家锁约束 |
| `biz.consult` | 就某条商机发起咨询，生成工单/会话 | 未开通 → `FORBIDDEN` |
| `biz.mark` | 标记商机（已联系/不感兴趣等） | 只影响本人视图 |
| `biz.delete` | 删除本人商机视图记录 | 不删除源需求/委托 |

管理端「客服业务」分三个页签：**佣金配置**（全局委托比例、超时分钟、各客服默认比例，仅管理员可改）、**每日工作量**（7/14/30 天按日明细与合计）、**客服与绑定**（绑定关系、锁定比例、业绩与工资；绑定/解绑仅管理员）。客服登录只读，前端隐藏写操作按钮且服务端白名单不含写动作。

佣金口径（客服佣金只有两项来源）：
1. 推广佣金：仅客服绑定用户可拿一级 + 二级（一级 `csLevel1Rate`、二级 `level2Rate`，默认各 15%），由推广中心按会员收款计提，进推广佣金台账，**不计入客服工资**；普通推广用户（含商机会员）只有一级佣金，按 `commissionRate` 计提。
2. 委托佣金 = 代采/代售服务费实收 × 委托佣金比例；同一 `paymentId` 只计提一次，进客服工资。比例为“绑定即锁定”——绑定关系建立时把当时生效的比例快照写入绑定，后续调价只影响新绑定。
3. 不设会员支付提成：会员付款只产生推广佣金，不再向客服计提。
4. 退款冲正：当月工资扣回；已发工资转欠款，从后续月份抵扣。
5. 评价只有咨询单所属用户在客服结束服务后提交一次，聚合进客服档案。

资金口径：
- 总营收 = 会员开通收入 + 委托服务费收入。会员部分统计实收 > 0 的会员订单：微信支付、手动开通（企业微信收款/对公转账）、线下登记均计入，实收 0 的赠送单不计；委托部分统计已确认到账的代采 / 代售 / 租赁服务费。两部分都进入 `revenue`、`byBizType`、`byChannel` 与近 6 个月趋势，财务中心可逐笔查看、修改备注与凭证。每周对账只核对微信支付渠道，Apple 走 Apple 账单、手动/线下单仅进台账与营收。
- 佣金设置入口：管理员可在「财务中心 → 佣金设置」或「推广管理 → 规则与对账」调整两组比例——客服绑定推广（一级 + 二级）与普通推广（仅一级，含商机会员），以及客服委托比例；两处读写同一份 `promoteSettings` / `csSettings`。「客服业务 → 佣金配置」单独维护客服委托比例（全局 + 单客服覆盖），客服账号只读。
- 手动开通同样生成 `MANUAL-<订单号>` 收款流水落 `payments`（通道 `manual`，0 通道费），与在线支付共用营收统计与推广佣金口径；客服不设会员提成。
- Apple 虚拟支付单独成表：财务总览按渠道拆出「微信支付 / Apple 内购 / 手动开通」三行，近 6 个月趋势带 Apple 营收列；Apple 不并入微信对账，佣金在确认到账后解冻。
- 退款顺序：先校验佣金回退 → 再置退款 → 再冲正各级佣金 → 再回退业务状态 → 最后通知。
- 提现手续费默认 5%，最低 100，单笔最高 20000，日累计 20000、日 3 次。

## 6. 跨模块主链路与状态机

### 6.1 会员购买与分佣链路

1. 用户选套餐 → 微信支付 → 支付回调进入 `grantMembership`。
2. 写 `bizOrders`（营收口径）→ 写 `payments`（收款流水）→ 延长 `bizAccess`。
3. 推广引擎按绑定关系计佣：客服绑定用户一级 + 二级（`csLevel1Rate` / `level2Rate`），普通推广仅一级（`commissionRate`）；`commissions` 二级用 `#L2` 后缀区分。
4. 客服不参与会员支付提成：会员付款只产生推广佣金。
5. 站内信通知用户；任一副链失败只记日志，不回滚会员开通。
6. 退款时按相反顺序冲正：推广佣金 → 会员权限停用 → 风险单。

### 6.2 代采代售全链路

`用户提交委托 → 平台审核上架 → 会员领取/客服对接 → 磋商条件 → 上传居间合同 → 管理员审核归档 → 锁定唯一对接方 → 确认成交 → 生成服务费账单 → 用户线下打款上传凭证 → 财务确认到账 → 计提客服委托佣金 → 客服确认完成`。

异常分支：
- 截止时间到未成交 → 自动关闭。
- 条件不成立 → 标记无效，工单结束。
- 服务费退款 → 委托回待支付、已完成退回已成交、工单阶段回退、佣金冲正。
- 多客服同时对接 → 合同上传后管理员/跟进客服锁定唯一对接方，其余结束。

### 6.3 推广提现链路

`佣金待结算 →（冻结期/Apple 到账）可提现 → 用户申请（冻结）→ 客服/财务审核 → 待打款 → 财务领取 → 打款中 → 回填成功 → 已到账`；驳回/撤销释放冻结；打款失败保持占用可重试。

### 6.4 工单与咨询阶段联动

- 工单状态（`leads.status`）负责“谁在跟进、是否成交/关闭”。
- 咨询阶段（`consultStage`）负责“交易走到哪一步、合同/服务费状态”。
- 两者通过 `agencyId / leadId` 关联；收款、退款、完成操作同时推进两边，避免出现“已成交但服务费未付”等不一致状态。

### 6.5 关键状态机汇总

| 对象 | 状态流转 |
| --- | --- |
| 商品 | 草稿 → 待审核 → 在售 → 洽谈中 → 已成交；旁路 已驳回/已下架 |
| 需求 | 草稿 → 待审核 → 求购中 → 已对接 → 已关闭；旁路 已驳回/已下架 |
| 工单 | 待分配 → 跟进中 → 已对接 → 已成交 → 已关闭；拦截 → 待分配/已关闭 |
| 委托 | 待审核 → 待确认 → 已通过 → 已上架 → 已锁定 → 待确认成交 → 已成交 → 已完成；旁路 已驳回/已关闭 |
| 咨询阶段 | 沟通中 → 条件已确认 → 合同待审核 → 合同已归档 → 服务费待支付 → 服务费已到账 → 已完成；旁路 已终止 |
| 合同 | 待审核 → 已归档；驳回/作废 |
| 收款 | 待确认 → 已确认 → 已退款 |
| 退款申请 | 待处理 → 已通过/已驳回/已撤销 |
| 会员 | 待确认 → 已开通 → 已到期；已停用 |
| 推广佣金 | 待结算 → 可提现 → 已提现；已冲正 |
| 提现 | 待审核 → 待打款 → 打款中 → 已到账；旁路 已驳回/已撤销/打款失败 |
| 居间合同 | 待审核 → 已归档；已驳回；已作废 |

## 8. 边界、异常与安全口径

1. **幂等**：支付回调、计佣、评价、收款确认、提现审核、退款处理均按唯一键或状态 CAS 幂等。
2. **越权**：所有“本人资源”动作先校验 `uid`；管理端先校验角色动作，再校验数据范围。
3. **金额**：统一两位小数；佣金、手续费分别四舍五入后再汇总，冲正按原单金额反向记账。
4. **时间**：统一北京时间（UTC+8）口径；月份键 `YYYY-MM`；到期时间从 `max(now, 原到期)` 顺延。
5. **删除**：业务数据以软删/状态关闭为主；审计、收款、佣金、合同不物理删除。
6. **失败补偿**：主业务成功后副链（通知、计佣）失败不回滚，由对账/补偿任务处理。
7. **敏感信息**：手机号/证件号/银行卡加密存储；列表脱敏；明文导出仅管理员并留审计。
8. **限流**：登录、验证码、咨询提交、搜索等按窗口计数；超限返回 `RATE_LIMITED`。
9. **错误码**：`VALIDATION`（参数）、`UNAUTHORIZED`（未登录）、`FORBIDDEN`（无权限）、`NOT_FOUND`、`CONFLICT`（状态冲突）、`RATE_LIMITED`、`INTERNAL`。
