# 算力聚合 · 角色使用说明

本文按「普通用户 / 客服坐席 / 管理员」三个角色，说明各自能做什么、不能做什么、业务如何流转，以及对应的后端动作与风控口径。

口径来源（逐条与代码核对）：

- 权限白名单：[rbac.js](../cloudbase/shared/rbac.js)
- 用户端动作：[handlers.user.js](../cloudbase/shared/handlers.user.js)、[market.js](../cloudbase/shared/market.js)
- 管理端动作：[handlers.admin.js](../cloudbase/shared/handlers.admin.js)、[market.js](../cloudbase/shared/market.js)
- 状态 / 限流 / 文案：[constants.js](../cloudbase/shared/constants.js)
- 自动化校验：[verify.mjs](../cloudbase/scripts/verify.mjs)

> 约定：任何写操作都由服务端重新校验，客户端传的价格、服务费、状态、档位一律不作数。

## 一、角色总览

| 角色 | 入口 | 身份凭证 | 能访问的页面 | 核心职责 |
| --- | --- | --- | --- | --- |
| 普通用户（企业 / 个人） | 微信小程序 | 微信登录态（openid） | 首页、发布、商机、消息、我的 | 发布货源 / 求购、咨询、代采代售、投稿、开通并领取商机 |
| 客服坐席（CS） | 管理端 | 账号 + 口令 + 动态口令（TOTP） | 商品池、求购池、咨询单、消息、商机、榜单、风险商品池 | 分派 / 转派工单、回复消息、确认代采代售到账、开通续费商机、查看实时在线与榜单 |
| 管理员（ADMIN） | 管理端 | 账号 + 口令 + 动态口令（TOTP） | 全部页面（含统计、拦截箱、规则、审计、账号、资讯、风险池） | 审核处置、线索状态推进、释放联系方式、账号与规则管理、资讯发布、风险商品打回 |

管理端登录规则：

- 同一账号 15 分钟内最多 5 次登录尝试，连续失败会被固定窗口限流。
- 登录态有效期 7 天，退出登录会注销会话并记审计。
- 管理端所有写动作都会写审计；审计日志只追加、不可修改。

## 二、普通用户（企业 / 个人）

### 2.1 登录与实名

1. 首次进入小程序自动注册并登录（`auth.login`）。
2. 在「我的」完善资料（`profile.save`）：昵称、手机号、真实姓名、主体名称、主体类型、城市、资质。
3. 编辑 / 发布前必须已有联系人姓名；手机号只以密文 + 盲索引落库，页面只回显脱敏号码。
4. 个人与企业都可用；企业建议填写统一社会信用代码与营业执照，便于客服核验。
5. 信息公开范围（`profile.save` 的 `exposure`，平台始终能看到状态）：

| 取值 | 页面文案 | 效果 |
| --- | --- | --- |
| `hidden` | 不公开主体 | 无法进入商机池，只能发布普通商品或需求；用户只能在站内消息联系到您；平台也不代转联系方式 |
| `open` | 公开主体 | 可发布同步到商机池的任务，商机会员可以直接添加微信和联系方式；普通页展示主体与联系人（手机号仍脱敏） |

> 历史数据中的 `matched`（对接后可见）已并入 `hidden`，按「不公开主体」处理，不会因此多暴露主体。
> 无论哪一档，手机号明文都不会出现在任何列表或详情响应里。只有「公开主体」的线索，管理员才可在「已对接」后释放手机号明文；「不公开主体」平台不代转，只能在站内会话沟通。

### 2.2 发布货源 / 求购

| 操作 | 动作 | 结果状态 |
| --- | --- | --- |
| 直接发布商品 | `product.publish` | 在售（立即对外可见，系统自动完成基础审核） |
| 存草稿后提交审核 | `product.submit` | 待审核（需要人工复核的场景） |
| 直接发布求购 | `demand.publish` | 求购中（立即对外可见，系统自动完成基础审核） |
| 存草稿后提交审核 | `demand.submit` | 待审核 |
| 编辑 | `product.update` / `demand.update` | 只改内容，不改状态；已成交 / 已关闭不可编辑 |

发布与审核口径：

- **发布即上架**：`product.publish` / `demand.publish` 成功即展示，服务端同步跑一遍基础审核，不进入人工审核队列，人工不审核也能正常展示。
- **自动审核命中风险**：命中价格异常、正文含联系方式、24 小时内同型号重复发布、信息过少等规则的条目，写入「风险商品池」（状态「待看」），但**照常展示、照常搜索、照常咨询**。
- **人工可选处置**：管理员在「风险商品池」查看后可「打回」（下架 + 填原因）或「排除」（保留展示）；不查看、不处理不影响任何内容。
- **草稿审核路径**：`product.submit` / `demand.submit` 仍保留「草稿 → 待审核」流程，供需要人工复核的品类使用。
- 浏览量：详情页与「我的 · 我发布的」都展示浏览量；同一访问者 30 分钟内只计一次，发布者自己浏览不计数。
- 可见范围：不再逐条选择，由「我的 · 信息公开范围」派生（公开主体 → 公开，不公开主体 → 保密），详见 2.5.1。保密内容照常走自动审核与风险池，只是不进商机池、不露主体与联系方式。

发布规则：

- 出售 / 求购为一次性成交，计价「元 / 台」，需填交易地与成色（出售方）。
- 出租 / 租赁按「元 / 台 / 月」计价，需填租期、押金、支付方式与租赁限制条款。
- 标题、说明、备注、必须条件中不允许出现手机号、微信号、身份证号等明文联系方式。
- 限流：商品 10 条 / 天、求购 5 条 / 天。
- 「必须条件」只能从平台白名单中选择，客户端提交未知条件会被拒绝。
- 材料（图片 / 视频 / 营业执照）只保存元信息，访问时用 5 分钟有效的临时签名链接。

商品状态机：

```
草稿 → 待审核 → 在售 → 洽谈中 → 已成交
                    ↘ 已下架 / 已驳回（平台处置，可再编辑）
```

求购状态机：

```
草稿 → 待审核 → 求购中 → 已对接 → 已关闭
                    ↘ 已下架 / 已驳回
```

### 2.3 我的库存（仅本人可见）

- 动作：`stock.list` / `stock.save` / `stock.remove`。
- 用途：只用于「商机匹配」，不对外展示，也不进入首页现货盘。
- 发布出售商品时可勾选「同步到我的库存」（`syncStock`）：勾选后自动写入一条库存（同一商品重复编辑只更新不重复插入）。平台新发布的求购需求会与这条货源匹配，商机在「商机」页查看。
- 上限 200 条；本地优先保存并静默同步云端，无云环境时也能正常使用。
- 下架库存不参与匹配；库存里的品类、型号、数量、城市越准确，匹配越准。

### 2.4 联系货主 / 需求方（咨询即开直聊）

1. 只能联系「在售」商品或「求购中」需求，不能联系自己发布的内容。
2. 必须逐项确认并勾选全部「必须条件」，任一项不满足无法提交；「可协商条件」不拦截，带进会话继续谈。
3. 同一手机号 + 同一对象 24 小时内只能提交一次；每账号每小时最多 10 次。
4. 提交后进入平台判档：
   - P0（手机号黑名单、敏感词等）：直接拦截，不通知对方，不进入客服队列；24 小时内可人工复核恢复。
   - P1（材料不足、跨品类等）：正常进入待分配，客服需先核对资质。
   - P2（预算达标、重点品类等）：在待分配队列中优先。
   - 默认：按提交时间排队。
5. 非 P0 的提交会立即开通与货主 / 需求方的站内直聊（会话 id 即咨询单 id）：
   - 页面提示「已开启对话」，可直接跳到「消息 - 对话」继续沟通；
   - 双方各持一份消息副本，第三方无法读取他人会话；
   - 消息里仍不允许出现手机号、身份证号等明文联系方式，主体仍按公开范围脱敏。
6. P0 回执固定为中性文案：「咨询已提交。若匹配，后台客服会进行联系，请不要重复发起咨询。」不承诺响应时长，也不透露是否被拦截。

### 2.5 代采 / 代售委托

适用场景：用户要买 / 要卖，但不想公开挂单，委托平台代为寻找或撮合。

流程：

```
填写委托 → 提交（agency.submit，发布 / 审核 / 上架均不收费）
        → 客服审核；1000 万元及以上同时核验资料
        → 客服确认（agency.confirm）→ 委托上架 30 天
        → 现货盘 / 商机池可见 → 撮合成功（管理员标记已成交）→ 成交后生成服务费账单
        → 到期自动移出
```

- 用户在小程序「我的 - 我的委托」查看进度：待确认 / 已上架 / 已成交 / 已关闭 / 已驳回，包含服务费、到期时间与驳回 / 关闭原因。
- 「待确认」的委托用户可自助撤销（`agency.cancel`）；已上架的委托需联系客服，由管理员关闭或标记成交。
- 客服确认、驳回、关闭 / 标记成交时都会给委托方发站内信，委托不会停在「待确认」无人处理。

- 提交时限流 5 条 / 天；同时进行中的委托最多 10 条。
- 服务费由服务端按「设备金额」重新计算，客户端传的 `serviceFee` / `upfront` 一律忽略。**代采 / 代售全部为成交后付费**，提交时前置款恒为 0：

| 成交金额 | 服务费 | 本次应付 | 说明 |
| --- | --- | --- | --- |
| ≤ 3 万元 | 299 元 / 单 | 0 元 | 成交后支付 |
| 3 万 - 100 万元 | 成交金额 × 1% | 0 元 | 最高 5000 元，成交后支付 |
| 100 万元以上 | 成交金额 × 0.5% | 0 元 | 上不封顶，成交后支付 |
| 首月租金合计（算力租赁） | 首月租金合计为一个月的服务费，买卖双方各承担 50%；委托方账单 = 月租金 × 数量 × 50% | 0 元 | 成交后支付 |

100 万元以上（含 1000 万元）代采 / 代售费率一致，均为成交金额 0.5%、上不封顶；1000 万元及以上另需资料核验。

1000 万元及以上代采 / 代售统一走资料核验，必须同时满足：

1. **代采**：采购意向函、委托授权书、联系人身份证三份材料齐全；企业主体还需营业执照；
2. **代售**：营业执照、货源证明、委托授权书、联系人身份证；个人主体可免营业执照；
3. 填写的联系人手机号需与委托授权书上的电话一致，提交时不做硬校验，由客服在核验环节比对；
4. 提交后不弹缴费码，客服在商机页看到「资料核验 · 成交后 0.5%」标记，核验通过后点「确认」上架。

- 租赁委托服务费为一个月租金，买卖双方各承担 50%，委托方账单金额 = 月租金 × 数量 × 50%，成交后支付；不因金额大小改为比例计费。
- 资金证明、营业执照等材料为选填；材料名会落库，文件路径不下发。
- 委托里的主体名称、手机号、法人、信用代码、身份证号全部密文落库，列表只给脱敏值。
- 委托有效期 30 天，到期自动从现货盘 / 商机池移出（数据保留，不物理删除）。
- 缴费走线下企业微信收款，系统不保存支付凭证；服务费在成交后由平台出账，退费按平台规则由客服线下处理，没有自动退款接口。

用户可在 `agency.mine` 查看自己的委托状态：待确认 / 已上架 / 已成交 / 已关闭 / 已驳回。

### 2.5.1 可见范围（公开 / 保密）

平台内所有对外内容都带可见范围字段 `visibility`：`public`（公开）或 `private`（保密）。

| 内容 | 可选范围 | 说明 |
| --- | --- | --- |
| 代采委托 | 1000 万元及以上仅平台可见 | 1000 万元及以上强制 `private`，不进入商机池与现货盘；其余公开给平台匹配 |
| 代售委托 | 公开 / 保密 | 公开进商机池；保密只有委托方与平台看得到 |
| 商品 / 需求 | 由主体公开范围派生 | 「公开主体」发布为 `public`；「不公开主体」发布为 `private`，可正常浏览但不进商机池 |

- 商品 / 需求的 `private` 只隐藏主体与联系方式：列表与详情仍展示内容，详情返回 `contactHidden`，站内对话不受限。
- 发布页不再单独选择可见范围；代采表单固定为「仅平台可见」。
- 管理端风险商品池与审核队列不过滤保密内容，平台始终能审。

### 2.6 现货盘与粘贴报价

- 首页「现货盘」由两部分聚合：
  - 已上架的代采 / 代售委托；
  - 用户 24 小时内提交的粘贴报价。
- 聚合维度：品类 + 型号 + 城市；买价取最高预算，卖价取最低报价。
- 粘贴报价（`quote.paste`）：
  - 把微信 / 群里的报价长文本粘贴进来，前端解析成「品类 / 型号 / 价格 / 城市」多条预览。
  - 服务端只保存结构化条目，**不保存原始长文本**，避免把聊天记录里的手机号、身份信息带入平台。
  - 24 小时有效；限流 10 次 / 天。
- 现货盘对已登录用户可见，不要求开通商机；商机权限只影响「领取联系方式」。

### 2.7 资讯

- 用户投稿：`news.submit`，标题 + 正文 + 城市，提交后为「待审核」。
- 管理员审核通过后才是「已发布」，首页资讯流才展示；驳回会记录原因。
- 正文不允许出现手机号、身份证号等联系方式。
- 投稿限流 5 篇 / 天。
- 官方资讯只能由管理员发布（`news.create`），用户不能伪造成官方。
- 管理端「资讯管理」页与后端同源：展示全部投稿与官方资讯，可按「全部 / 待审核 / 已发布 / 已下架 / 已驳回」筛选并支持关键词搜索；顶部展示待审核、已发布、已下架数量。
- 管理员在该页可直接发布官方资讯、审核投稿、下架已发布内容；客服账号无资讯权限（`news.create` / `news.review` / `news.offline` 返回 FORBIDDEN）。

### 2.8 商机（99 元 / 月）

开通流程：

```
用户申请（biz.apply）→ 状态「待确认」→ 客服确认收款（biz.grant）→ 状态「已开通」
→ 有效期 30 天 → 续费按剩余有效期累加 30 天
```

领取条件（两个条件必须同时满足）：

1. 商机权限在有效期内（已开通，未到期、未被停用）；
2. 「我的库存」与目标需求 / 委托在品类或型号上匹配成功。

商机池展示规则：

- 所有「求购中」的需求都展示，未开通时只给脱敏主体与「开通商机后可见」提示；**保密需求不进入商机池**。
- 代采 / 代售委托只展示与本人库存匹配的条目；**代采强制仅平台可见，不进商机池**，保密的代售也不进。
- 联系方式只对「已开通 + 已匹配 + 已领取」的本人释放一次；重复领取幂等返回同一号码。
- 同一条商机不设领取名额上限，只要是商机会员且库存匹配都可领取；列表展示「已有 N 家领取」，同一商家重复领取幂等。
- 商机页可展开「囤货榜单」：GPU / 内存 / CPU / NPU / 存储 / 网络 品类榜、型号榜、今日搜索热词与搜索最多的商品。
- 权限到期或被停用后，已领取记录保留，但不再下发联系方式，页面提示续费。
- 申请限流 3 次 / 天；`biz.status` 可随时查询权限状态与到期时间。

> 商业规则说明：商机费是信息服务费，不承诺成交；一个月未成交的退费按平台规则线下处理，系统不自动退款。

### 2.9 消息与我的

- `msg.list` / `msg.read` / `msg.send`：与平台客服沟通；`msg.thread` 按会话 id 读取与货主 / 需求方的直聊记录（只有线索参与方可读）。消息内容不允许包含手机号等明文联系方式（平台侧统一拦截）。
- `fav.set` / `fav.list`：收藏商品 / 求购，云端保存，换手机登录后自动恢复。收藏不通知对方，货主看不到谁收藏了自己。
- `follow.set` / `follow.list`：关注货主。服务端只下发不可逆的匿名货主键（`ownerKey`），关注记录只保存这个键与展示用昵称 / 城市，不落对方 openid，也不泄露身份。
- 收藏 / 关注都是「本地缓存 + 云端同步」：本地立即生效保证首屏与离线可用；推送失败进待同步队列，下次进入「我的」自动补发。本地与云端一致时以云端为准（换设备的取消操作也能同步下来），存在未落库的本地变更时取并集，避免刚收藏就被覆盖。
- 本地优先口径（对齐微信模式，降低服务器压力）：
  - **只留本地，不上云**：浏览记录、筛选条件、表单草稿、文件选择结果、已读状态等纯本机数据。
  - **关系数据上云做备份**：收藏、关注本地常驻，云端只存一份用于换机恢复；服务端按 `since` 只返回变化行（`removed` 告知取消项），不做全量下发。
  - **节流**：同一端 5 分钟内不重复对账；「我的」页的发布 / 咨询 / 委托各存本地快照，60 秒内直接读快照不回源。
  - **合并写入**：连续点收藏 / 关注先入本地队列，800ms 合并成一批推送；离开页面时立即补发。
  - **失效标记**：发布 / 编辑 / 咨询成功后置脏，回到「我的」强制刷新一次。
- `mine.list` / `mine.publish.list` / `mine.publish.detail`：查看自己的咨询、发布与状态。
- 用户端所有列表都只返回脱敏信息；联系方式只在明确的「领取 / 释放」动作后返回。

## 三、客服坐席（CS）

### 3.1 登录

- 管理端账号 + 口令 + 动态口令；15 分钟内最多 5 次尝试；登录态 7 天。
- 客服没有「创建账号 / 重置口令 / 查看审计」权限。

### 3.2 可执行动作

| 模块 | 允许动作 | 说明 |
| --- | --- | --- |
| 商品池 | `product.list` | 只读，查看商品与状态 |
| 求购池 | `demand.list` | 只读，查看求购与状态 |
| 咨询单 | `lead.list` / `lead.detail` | 只读，按档位、状态、坐席筛选 |
| 工单分配 | `lead.assign` | 分配 / 转派给启用中的坐席，必须是真实账号 |
| 坐席列表 | `staff.list` | 分配下拉、服务记录筛选 |
| 消息 | `msg.threads` / `msg.list` / `msg.read` / `msg.reply` | 回复用户消息；可见范围见下方说明 |
| 代采代售 | `agency.list` / `agency.confirm` / `agency.reject` | 「商机管理」页的「代采 / 代售委托单」面板：核对资料 / 收款后确认；资料不合格可驳回（原因会站内信通知委托方） |
| 商机 | `biz.list` / `biz.grant` | 查看开通申请与领取记录；确认收款后开通 / 续费 |
| 榜单与在线 | `insights.board` / `insights.searches` / `insights.boards` | 只读：实时在线人数、每日搜索热词、每日搜索最多的商品、品类与型号榜 |
| 风险商品池 | `risk.list` | 只读：查看系统标记的风险商品 / 求购 |

**会话可见范围**

- 管理员：全量会话（对账、投诉核查需要）。
- 客服：只看「本人跟进过」的用户 + 尚无处理人的公共池用户。
  - 用户没有任何咨询线索（纯客服留言）→ 公共池，任何客服都能接待，避免新用户找不到人。
  - 用户有线索但都未分配 → 公共池，客服可先看再分配给自己。
  - 用户线索已分配给其他坐席 → 不可查看、不可回复、不可标记已读（`FORBIDDEN`），会话列表里也不再出现。
- 抢单：公共池的线索用 `lead.assign` 认领到自己名下；认领后其他客服即不可见。会话每次查看 / 回复都有审计留痕。

### 3.3 明确不能做（会返回 FORBIDDEN）

- 变更线索状态（`lead.updateStatus`）——只有管理员能推进「已对接 / 已成交」。
- 释放联系方式（`contact.reveal`）——只有管理员能释放，且必须填写不少于 5 字的查看原因；对方为「不公开主体」时一律拒绝，平台不代转。
- 商品 / 求购审核、下架、重新上架。
- 关闭代采 / 代售委托、标记成交（`agency.close`）。
- 停用商机权限（`biz.revoke`）。
- 资讯发布 / 审核 / 下架（`news.create` / `news.review` / `news.offline`）。
- 处置风险商品（`risk.handle`）——客服只能看风险池，打回 / 排除由管理员操作。
- 粘贴报价清理（`quote.list` / `quote.remove`）。
- 统计、拦截箱、规则、审计、账号管理、用户数据。

### 3.4 客服标准作业

1. 打开咨询单列表，按档位排序：P0 已拦截不进队列；P1 先核资质；P2 优先响应。
2. 把工单分配给自己或组员（`lead.assign`），在消息里与用户确认需求。
3. 需求真实、条件匹配后，请管理员把线索推进到「已对接」；对方为「公开主体」时再由管理员释放联系方式，「不公开主体」不释放，引导双方在站内会话沟通。
4. 用户提交代采 / 代售委托后（1000 万元及以上为资料核验，均不预收费），在商机页找到委托，核对资料，点「确认」上架；成交后按服务费账单核对到账。
5. 用户支付 99 元商机费后，在商机页找到申请，点「开通 / 续费」。
6. 所有确认 / 驳回 / 开通动作都会进入客服服务记录，可在管理端按坐席统计。

## 四、管理员（ADMIN）

管理员拥有客服的全部权限，并额外拥有以下能力。

### 4.1 商品与求购处置

- `product.review`：通过 / 驳回（驳回需原因）；通过后在售，驳回后用户可编辑再提交。
- `product.setStatus` / `product.offline` / `product.online`：下架、重新上架、按需改状态。
- `demand.review` / `demand.setStatus` / `demand.offline` / `demand.close`：审核、下架、关闭求购。

### 4.2 线索全流程

状态机（只允许以下流转，其余返回 CONFLICT）：

```
已拦截 → 待分配 / 已关闭        （待分配仅限 24 小时复核窗口内，且必须填原因）
待分配 → 跟进中 / 已关闭
跟进中 → 已对接 / 待分配 / 已关闭
已对接 → 已成交 / 已关闭
已成交 → 已关闭
已关闭 → （终态）
```

- 「已对接」必须目标商品 / 需求处于可对接状态；同一商品 / 需求同时只能有一条「已对接」或「已成交」线索。
- 线索推进到「已对接 / 已成交」会联动商品 / 需求状态，失败会回滚。
- `contact.reveal`：仅「已对接 / 已成交」且对方为「公开主体」时可释放，需填写 ≥5 字原因；「不公开主体」平台不代转，调用会返回 CONFLICT。释放动作写审计，且会标记线索已释放。
- `lead.assign` 的分配与转派都会留痕；代采 / 代售等平台对接项目不设用户「优先」标记，管理端按资料与主体信息齐全度排序处理。
- 线索推进到「已对接 / 已成交 / 已关闭」会给咨询人发站内信（带 `leadId`），用户端在「消息」里查看进展；平台咨询只用于代采 / 代售委托，商品与需求由双方站内会话沟通。

### 4.3 交易服务处置

- `agency.close`：关闭委托，或标记「已成交」。
- `news.create`：直接发布官方资讯。
- `news.review`：审核用户投稿（通过 / 驳回 + 原因）。
- `news.offline`：下架已发布资讯。
- `quote.list` / `quote.remove`：查看与清理粘贴报价（软删，24 小时后自然失效）。
- `biz.revoke`：停用商机权限，立即生效；已领取记录保留但不再下发联系方式。
- `risk.handle`：把风险商品 / 求购「打回」（下架并记录原因）或「排除」（保留展示，标记已看过）。
- `insights.board` / `insights.searches` / `insights.boards`：实时在线人数、每日搜索热词、每日搜索最多的商品、品类与型号榜。管理端「统计」页直接展示这些指标；「榜单」页可下钻品类与型号热度。

### 4.4 平台治理

- `stats.overview`：核心指标。
- `blocked.list`：已拦截线索与复核倒计时（24 小时内可恢复，30 天未复核自动清理）。
- `rules.list` / `rule.create` / `rule.update` / `rule.toggle`：筛选规则与判档口径。
- `audit.list`：审计日志（只追加，保留 180 天）。
- `service.records`：客服服务记录（分配、状态推进、释放联系方式、回复、代采确认、商机开通）。
- `users`：`user.list` / `user.detail`，只给脱敏信息。
- `accounts`：`account.list` / `account.create` / `account.update` / `account.resetPassword`。

## 五、全流程走查（按角色串联）

### 5.1 发布 → 直接对话 → 成交

1. 用户 A 发布商品（`product.publish`）→ 状态「在售」并立即展示，服务端同步做基础自动审核（命中风险只进风险池，不影响展示）；勾选「同步到我的库存」时同时写入一条库存（`stockSynced: true`），用于与平台新发布的求购需求做商机匹配。
2. 用户 B 浏览并点「联系货主 / 需求方」（`consult.submit`）：勾选全部必须条件 → 服务端判档 → 生成线索。
3. P0 → 已拦截（用户看到中性回执，不开会话）；P1 / P2 / 默认 → 待分配，并立即开通 A、B 之间的直聊（`threadId` = 线索 id），B 可直接在「消息 - 对话」沟通。
4. 双方在直聊里确认可协商条件（`msg.thread` / `msg.send`）；不公开主体只能站内私聊，平台不代转联系方式。
5. 客服分配工单（`lead.assign`）→ 跟进中。
6. 管理员推进「已对接」（`lead.updateStatus`）→ 商品变「洽谈中」，其他咨询单不能重复对接。
7. 对方为「公开主体」时，管理员释放联系方式（`contact.reveal`）→ 返回手机号明文 + 写审计；「不公开主体」不释放，仅保留站内会话。
8. 管理员推进「已成交」→ 商品变「已成交」；再关闭线索（可选）。

### 5.2 代采 / 代售

1. 用户提交委托（`agency.submit`）→ 服务端重算服务费，发布时不收费；1000 万元及以上进入资料核验。
2. 客服审核资料 / 委托内容；大额委托需资料齐全后上架。
3. 客服确认（`agency.confirm`）→ 委托「已上架」30 天，进入现货盘 / 商机池（代采与保密委托除外）。成交后按服务费账单收款。
4. 有匹配库存且已开通商机的用户领取（`biz.claim`）→ 得到委托方联系方式。
5. 撮合成功，管理员标记「已成交」（`agency.close`）；未成交则 30 天后自动移出现货盘。

### 5.3 商机开通 / 续费 / 停用

1. 用户申请（`biz.apply`）→ 待确认。
2. 客服确认收款（`biz.grant`）→ 已开通，有效期 +30 天。
3. 再次开通按剩余有效期累加（续费）。
4. 管理员停用（`biz.revoke`）→ 立即失效；用户 `biz.status` 变为「已停用」。

### 5.4 资讯投稿

1. 用户投稿（`news.submit`）→ 待审核，不对外展示。
2. 管理员在管理端「资讯管理」页审核（`news.review`）→ 通过则发布，驳回需填原因。
3. 管理员可下架（`news.offline`），下架原因会展示在列表里。
4. 官方资讯由管理员直发（`news.create`），列表带「官方」标签。

### 5.5 库存匹配

1. 用户在「我的库存」维护品类 / 型号 / 数量 / 城市（最多 200 条）。
2. 商机页读取本人库存，对每条需求 / 委托做品类 + 型号匹配。
3. 匹配成功且已开通 → 可领取；未开通只展示脱敏信息。
4. 库存变化后下次刷新即生效；已领取记录不因库存删除而回收（但权限到期后不再下发联系方式）。

### 5.6 商品发布自动审核与风险池

1. 用户发布商品（`product.publish`）→ 立即「在售」，同时服务端做基础审核。
2. 命中规则的条目写入风险池，状态「待看」，不影响展示：
   - `price_outlier`：GPU 类目单价低于 1 万或高于 1 亿；
   - `contact_in_text`：标题 / 正文里出现手机号、微信等联系方式；
   - `repeat_listing`：24 小时内同型号发布 ≥ 3 条；
   - `low_information`：标题与描述信息过少。
3. 管理员在管理端「风险商品池」逐条查看：确认正常点「排除」（保留展示），确认违规点「打回」（下架 + 填原因）。
4. 客服可查看风险池，但处置按钮不展示；调用 `risk.handle` 会返回 FORBIDDEN。
5. 浏览量在商品 / 求购详情页展示，同一访问者 30 分钟内只计一次，发布者自己浏览不计数；「我的 · 我发布的」列表也展示每条货源 / 求购的浏览量。
6. 管理端「统计」页展示实时在线人数（5 分钟心跳）、今日搜索热词、每日搜索最多的商品、品类榜与型号榜；「榜单」页可下钻品类与型号热度，辅助商家囤货。
7. 榜单口径：按 `boardScopeOf` 归入 GPU / 内存 / CPU / NPU / 存储 / 网络 / 其他；品类榜按浏览量、咨询量排序；型号榜按同型号聚合（货源数、数量、浏览、咨询、均价）；「今日搜索最多」把当日搜索词落到在售型号后按搜索量排序，同一搜索词只给命中型号加一次。
8. 用户端「商机」页可展开「囤货榜单」，与管理员榜单同源（`insights.market`），但不返回联系方式与身份信息。

## 七、当前边界与待补项

以下是代码现状，使用与验收时需要注意：

1. 管理端没有独立的「代采 / 代售」页面，委托单处理已并入「商机管理」页顶部的「代采 / 代售委托单」面板。
2. 小程序「我的 - 我的委托」已接入 `agency.mine` / `agency.cancel`，可看状态与自助撤销待确认委托；商机权益卡在「商机」页展示。
3. 商机页在未连云端时保留本地演示数据兜底；接入云端后不再出现「原型演示：模拟客服已开通」，开通一律走 `biz.apply` 由客服确认收款。
4. 支付为线下企业微信收款，系统只记录服务费金额与到账确认，不保存支付凭证，也没有自动退款接口。
5. 资讯正文目前只做联系方式拦截与长度校验，没有做富文本 / 图片能力。
6. 榜单、实时在线、每日搜索最多商品依赖埋点（浏览、搜索、心跳）；本地演示数据不产生这些指标，连接云端后才显示真实数值。
7. 商机领取不设名额上限，商机会员且库存匹配即可领取；小程序发布表单也不再提供 `claimLimit` 配置。
