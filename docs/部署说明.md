## 2. 目录映射（本地 → 服务器）

服务器目录不是 git 检出，部署就是把本地这三个目录 rsync 过去：

| 本地（本仓库） | 服务器 | 说明 |
| --- | --- | --- |
| `cloudbase/shared/` | `/opt/suanli-platform/shared/` | 全部业务逻辑（handlers / market / rbac / constants…） |
| `cloudbase/server/` | `/opt/suanli-platform/server/` | HTTP 服务入口 `index.js`、MySQL 仓储 `repo.mysql.js`、`payout.js`、`seed.js` |
| `prototype/` | `/opt/suanli-platform/public/` | 管理端静态页；`public/uploads/` 是线上用户上传，**同步时不要覆盖** |

服务器侧其他文件（不要用本地覆盖）：

- `/opt/suanli-platform/.env`：生产密钥（MySQL、AES/HMAC、微信 AppSecret、管理员/客服/财务初始账号、`WX_XPAY_*` 等）
- `/opt/suanli-platform/ecosystem.config.cjs`：PM2 配置（PORT/HOST/ENV_FILE/日志路径）
- `/opt/suanli-platform/scripts/backup-db.sh`、`health-watchdog.sh`：备份与巡检脚本

## 3. 标准部署步骤

### 3.1 部署前自检（本地）

```bash
cd /Users/raoxiaobao/Desktop/算力交易平台
node cloudbase/scripts/verify.mjs          # 离线业务校验，应为「N 通过 / 0 失败」
npm run check --prefix cloudbase           # WXML + 小程序引用检查
git status && git log --oneline -3         # 确认改动都已提交
```

### 3.2 服务器备份

```bash
ssh root@114.55.251.166
TS=$(date +%Y%m%d-%H%M)
tar czf /opt/suanli-backup/pre-deploy-$TS.tar.gz \
  -C /opt/suanli-platform --exclude=public/uploads shared server public
```

### 3.3 上传代码（本地执行）

```bash
cd /Users/raoxiaobao/Desktop/算力交易平台
RS="ssh -S /tmp/suanli-deploy.sock"        # 复用长连接，见下方「排错」

rsync -az -e "$RS" --exclude '._*' --exclude '.DS_Store' \
  cloudbase/shared/ root@114.55.251.166:/opt/suanli-platform/shared/

rsync -az -e "$RS" --exclude '._*' --exclude '.DS_Store' \
  cloudbase/server/ root@114.55.251.166:/opt/suanli-platform/server/

rsync -az -e "$RS" --exclude '._*' --exclude '.DS_Store' --exclude 'uploads' \
  prototype/ root@114.55.251.166:/opt/suanli-platform/public/
```

> 不要加 `--delete`：服务器 `shared/` 里有历史 `.bak`，`public/` 里有 `uploads/`。
> macOS 的 `._*`（AppleDouble）必须排除，否则会在服务器留下垃圾文件。

### 3.4 重启并验证

```bash
ssh root@114.55.251.166 'pm2 restart suanli-platform --update-env && sleep 3 && pm2 list | grep suanli'
curl -s https://sljh.qining.xin/api/health
curl -s -o /dev/null -w '%{http_code}\n' https://sljh.qining.xin/admin/
```

健康检查正常返回示例：

```json
{"ok":true,"service":"suanli-platform","db":true,"cache":{...},"now":1794888487888}
```

必须看到 `"ok":true` 且 `"db":true`；若 `db:false` 先查 MySQL 与 `.env` 的 `MYSQL_URL`。

### 3.5 回滚

```bash

cd /opt/suanli-platform
tar xzf /opt/suanli-backup/pre-deploy-<时间>.tar.gz -C /opt/suanli-platform
```

## 5. 管理端版本号与缓存策略

管理端是「无构建直出脚本」，升级后最容易出现「服务器已是新版、浏览器还是旧页面」。约定如下：

**版本号位置**：`prototype/admin/index.html` 顶部

```html
<script>window.CONSOLE_VERSION = '2026.11.18-1141'</script>
<link rel="stylesheet" href="../assets/console.css?v=2026.11.18-1141">
...
<script src="../assets/console.core.js?v=2026.11.18-1141"></script>
<script src="../assets/console.pages.js?v=2026.11.18-1141"></script>
```

**升级管理端的固定动作**：

1. 改 `prototype/admin/index.html`：把日期-时分的版本号改成当前时间，**四处一起替换**（`CONSOLE_VERSION` + css + core.js + pages.js）
2. 部署 `prototype/` 到 `public/`（见 3.3）
3. 页面会直接展示这个版本号，便于用户报问题时核对：
   - 登录页左下「管理端版本 v2026.11.18-0100」
   - 登录后右上角 `v2026.11.18-0100`
4. 在下面的版本记录里补一行

**缓存策略**（服务器 nginx `/etc/nginx/conf.d/sljh.conf`，已改好）：

- `/admin/` → `expires -1`（HTML 每次协商）
- `/assets/` → `expires -1`（脚本/样式每次协商，ETag 304 开销很小）
- 以前 `/assets/` 是 `expires 7d`，升级后旧 JS 会在浏览器里留 7 天，这是「管理端看起来没更新」的根因，已修正
- 仍保留 `?v=` 版本串：换版本即换缓存键，双保险

## 6. 运维机制（已配置，无需手动）


- **每日冷备**：cron `40 2 * * *` 执行 `scripts/backup-db.sh`，落 `/opt/suanli-platform/backups/`，保留 7 天
- **健康巡检**：cron `*/2 * * * *` 执行 `scripts/health-watchdog.sh`，连续 2 次探测失败才 `pm2 restart`，日志 `health-watchdog.log`
- **开机自启**：`pm2-root.service` enabled，PM2 状态在 `/root/.pm2/dump.pm2`
- **证书续期**：`certbot.timer` enabled
- 定时任务（推广结算/对账/超时提醒等）在进程内启动，日志见 `out.log` 的 `[promote]` 行


改 `.env` 后必须 `pm2 restart suanli-platform --update-env` 才生效。

- `WX_XPAY_ENV=0`：正式环境，真实扣款，仅**正式版**小程序可用；`1`：沙箱，仅安卓真机可用，微信会弹「测试环境，请勿充值」提示，iOS 无法付款。
- 开发版 / 体验版必须用沙箱（`1`），正式版必须用 `0`，否则微信报 -15011「支付环境不匹配」。
- `WX_XPAY_APP_KEY` 必须与 `WX_XPAY_ENV` 配对：`0` 用「虚拟支付 → 基本配置 → 现网AppKey」，`1` 用同一页的「沙箱AppKey」。两把 key 混用会在拉起收银台时报 -15006「支付签名错误」（`paySig` 校验失败）。

## 8. 排错备忘

- **`ssh: connect to host ... port 22: Connection refused`**：短时间并发/连续建连会被拒（服务器侧限流）。等 60 秒再试，或先建复用连接：
  ```bash
  ssh -o ControlMaster=auto -o ControlPath=/tmp/suanli-deploy.sock -o ControlPersist=900 -fnNT root@114.55.251.166
  ```
  后续 `ssh -S /tmp/suanli-deploy.sock root@...` 与 `rsync -e "ssh -S /tmp/suanli-deploy.sock"` 都走这条连接。
- **部署后接口 500**：先看 `/var/log/suanli-platform/error.log`；多数是 `shared/` 少文件或语法错误，可 `node -c`（Node 22 用 `node --check`）单文件排查。
- **管理端页面没更新**：先看页面右上角 `v...` 是否等于最新版本；不一致时强刷一次（⌘⇧R）。`/admin/` 与 `/assets/` 现在都是 `expires -1`，正常刷新就会拉新。
- **上传附件 404**：`/uploads/chat/` 由 nginx 直接 `alias` 到 `/opt/suanli-platform/public/uploads/chat/`，同步时务必保留该目录。
- **不要**在服务器上改动 `shared/`、`server/`、`public/` 的源码：下次 rsync 会被覆盖，改动一律回本地仓库改再部署。
- 云函数 `cloudbase/cloudfunctions/{admin,user}` 仅在走云开发链路时才有意义，当前小程序直连 `sljh.qining.xin`，**部署 ECS 不需要发布云函数**。
